Oui. La **description d’une UA doit décrire l’apprentissage**, pas le livrable ni le résultat produit.

Je corrige donc les trois UA en gardant une progression directement liée à ton planning CSS.

### UA.122.21 — Débutant

**Code :** `UA.122.21`
**Titre :** Comprendre et appliquer les bases de CSS

**Description :**
Apprendre la syntaxe CSS, la liaison entre HTML et CSS et les sélecteurs de base. Apprendre à mettre en forme les textes, les couleurs, les arrière-plans et les images. Apprendre à contrôler les dimensions, les espacements, les bordures et l’affichage des éléments.

---

### UA.122.22 — Intermédiaire

**Code :** `UA.122.22`
**Titre :** Organiser la mise en page avec CSS

**Description :**
Apprendre à utiliser les sélecteurs avancés, le positionnement, Flexbox et Grid pour organiser les éléments d’une interface. Apprendre à contrôler les dimensions avec différentes unités et à construire une mise en page adaptée à la structure de l’interface.

---

### UA.122.23 — Avancé

**Code :** `UA.122.23`
**Titre :** Professionnaliser une interface avec CSS

**Description :**
Apprendre à adapter une interface aux différentes tailles d’écran avec le responsive design. Apprendre à gérer la cascade, l’héritage et la spécificité. Apprendre à utiliser les variables CSS, les pseudo-classes, les transitions, les transformations et les animations pour construire des styles plus robustes et plus avancés.

### Cohérence avec le domaine

`D.122.2 — Mettre en forme une interface avec CSS`

→ **UA.122.21 :** apprendre les bases et les règles de mise en forme
→ **UA.122.22 :** apprendre l’organisation de la mise en page
→ **UA.122.23 :** apprendre l’adaptation et les comportements avancés

Ainsi, **l’objectif de l’UA décrit ce que l’apprenant apprend**, tandis que la réalisation et le livrable seront définis séparément.
