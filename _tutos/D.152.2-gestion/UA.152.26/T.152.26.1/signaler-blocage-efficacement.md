## 1. Objectif

Vous allez apprendre à signaler un blocage de manière claire.

Vous allez apprendre à :

- expliquer ce que vous voulez faire ;
- décrire ce qui se passe ;
- indiquer ce que vous avez déjà essayé ;
- expliquer l'impact du blocage ;
- demander une aide précise.

## 2. Prérequis

Vous devez savoir :

- identifier une tâche ;
- utiliser un tableau de suivi ;
- distinguer une tâche terminée d'une tâche bloquée ;
- décrire simplement un problème.

## Données de départ

### Contexte

Vous travaillez sur la partie **Administration** du Blog.

Vous devez gérer les catégories des articles.

Une tâche de votre planning est :

> **Ajouter une catégorie.**

Vous essayez d'enregistrer une nouvelle catégorie.

Mais la catégorie ne s'enregistre pas.

Vous êtes bloqué.

Vous devez maintenant signaler ce blocage.

## Partie 1 — Théorie

### 1.1. Un blocage

Un **blocage** est un problème qui empêche de continuer une tâche.

Exemple :

> Je ne parviens pas à enregistrer la catégorie.

La tâche ne peut pas continuer normalement.

Il faut donc signaler le problème.

### 1.2. Un signalement efficace

Un bon signalement donne les informations nécessaires pour comprendre le problème.

Il répond à cinq questions :

1. Qu'est-ce que je veux faire ?
2. Qu'est-ce qui se passe ?
3. Qu'ai-je essayé ?
4. Quel est l'impact ?
5. De quelle aide ai-je besoin ?

### 1.3. Ce que je veux faire

Commencez par expliquer l'action attendue.

Exemple :

> Je veux ajouter une nouvelle catégorie.

Cette information permet de comprendre le but de la tâche.

### 1.4. Ce qui se passe

Décrivez le résultat obtenu.

Exemple :

> Je remplis le formulaire et je valide. La catégorie n'apparaît pas dans la liste.

Décrivez ce que vous observez.

Évitez une phrase trop générale comme :

> Ça ne marche pas.

### 1.5. Ce que vous avez essayé

Indiquez les actions déjà réalisées.

Exemple :

> J'ai vérifié le nom de la catégorie.  
> J'ai rempli tous les champs.  
> J'ai essayé une deuxième fois.

Cette information évite de refaire les mêmes actions.

### 1.6. L'impact

Expliquez ce que le blocage empêche de faire.

Exemple :

> Je ne peux pas continuer la gestion des articles avec cette catégorie.

L'impact montre pourquoi le problème doit être traité.

### 1.7. Le besoin

Terminez par une demande claire.

Exemple :

> J'ai besoin d'aide pour trouver pourquoi la catégorie ne s'enregistre pas.

La personne qui vous aide sait ainsi ce que vous attendez.

### 1.8. La structure d'un message SOS

Vous pouvez utiliser cette structure :

| Élément | Question |
|---|---|
| Attendu | Que voulais-je faire ? |
| Observé | Que se passe-t-il ? |
| Tentatives | Qu'ai-je déjà essayé ? |
| Impact | Qu'est-ce qui est bloqué ? |
| Besoin | Quelle aide me faut-il ? |

### 1.9. À retenir

Un bon signalement est :

- clair ;
- précis ;
- court ;
- basé sur des faits ;
- orienté vers une demande d'aide.

Évitez simplement :

> Ça ne marche pas. Aidez-moi.

Préférez un message qui explique le problème et les actions déjà réalisées.

## Partie 2 — Pratique

### 2.1. Décrire le blocage

Reprenez la situation :

> Vous devez ajouter une catégorie dans l'espace d'administration du Blog, mais la catégorie ne s'enregistre pas.

Complétez le tableau.

| Élément | Votre réponse |
|---|---|
| Attendu | |
| Observé | |
| Tentatives | |
| Impact | |
| Besoin | |

Utilisez des phrases courtes.

### 2.2. Améliorer un message

Voici un mauvais signalement :

> Je suis bloqué. Ça ne marche pas. Je ne sais pas quoi faire.

Le message ne donne pas assez d'informations.

Transformez-le en message structuré.

Utilisez les cinq éléments :

- attendu ;
- observé ;
- tentatives ;
- impact ;
- besoin.

### 2.3. Rédiger le message SOS

À partir de votre tableau, rédigez un message.

Vous pouvez utiliser cette structure :

> **SOS — Ajout d'une catégorie**
>
> **Attendu :** …
>
> **Observé :** …
>
> **Tentatives :** …
>
> **Impact :** …
>
> **Besoin :** …

Le message doit permettre à une autre personne de comprendre rapidement votre blocage.

### 2.4. Vérifier le message

Relisez votre message.

Vérifiez chaque élément.

| Question | Oui / Non |
|---|---|
| Ai-je expliqué ce que je voulais faire ? | |
| Ai-je décrit ce qui se passe ? | |
| Ai-je indiqué mes tentatives ? | |
| Ai-je expliqué l'impact ? | |
| Ai-je demandé une aide précise ? | |

Corrigez les informations manquantes.

### 2.5. Appliquer la méthode à votre travail

Prenez un blocage réel rencontré pendant votre travail sur l'administration du Blog.

Il peut concerner :

- l'ajout d'une catégorie ;
- une autre tâche de gestion ;
- une tâche qui empêche de continuer.

Décrivez le blocage avec les cinq éléments.

Si vous n'avez aucun blocage réel, utilisez le cas de l'ajout d'une catégorie présenté dans ce tutoriel.

### 2.6. Produire le livrable

Rédigez votre message **SOS** final.

Il doit présenter :

- le résultat attendu ;
- le problème observé ;
- les tentatives réalisées ;
- l'impact ;
- le besoin.

**Livrable :**

Créez un document Markdown (ou un Google Doc) contenant votre message **SOS** structuré.

**Critère de réussite :**

Le message permet de comprendre le blocage sans demander immédiatement une nouvelle explication. Il indique ce qui était attendu, ce qui est observé, les tentatives réalisées, l'impact et l'aide demandée.

## Bilan

**Vous avez réalisé :** un message SOS structuré pour signaler un blocage.

**Vous savez maintenant :** expliquer un problème, présenter vos tentatives et demander une aide précise.

## Glossaire

- **Blocage** : problème qui empêche de continuer une tâche.
- **Attendu** : résultat que vous vouliez obtenir.
- **Observé** : résultat que vous obtenez réellement.
- **Tentative** : action déjà réalisée pour résoudre le problème.
- **Impact** : conséquence du blocage sur votre travail.
- **Besoin** : aide nécessaire pour continuer.
