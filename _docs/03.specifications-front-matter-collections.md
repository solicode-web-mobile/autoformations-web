# Spécifications du Front Matter des Collections Jekyll

## 1. Vue d'Ensemble

Le **Front Matter** est le bloc de métadonnées au format YAML placé au tout début de chaque fichier Markdown, délimité par des triples tirets `---`.

Jekyll utilise ces métadonnées pour :
- Associer la page à son gabarit HTML (`layout`).
- Configurer l'URL de publication (`permalink`, `slug`).
- Établir les liens dynamiques entre les entités (ex: relier une Session à ses UAs, ou un Tutoriel à son UA parente).
- Fournir les textes affichés par les gabarits Liquid (titres, objectifs, consignes, listes de livrables).

Ce document détaille la spécification complète de chaque collection avec ses champs obligatoires, optionnels et un exemple type prêt à l'emploi.

### 2.1. Collection `sessions` (`_sessions/S[X].md`)

Les fichiers de session pilotent l'affichage du parcours hebdomadaire et regroupent les 4 phases d'apprentissage.

#### Tableau des Champs

| Champ | Type | Obligatoire | Rôle & Description |
| :--- | :--- | :---: | :--- |
| `layout` | Chaîne | **Oui** | Doit impérativement être `session`. |
| `title` | Chaîne | **Oui** | Titre complet de la session (ex: `"S1 — Premiers pas dans le Web"`). |
| `code` | Chaîne | **Oui** | Identifiant court unique de la session (ex: `"S1"`). Sert de clé de liaison. |
| `tuto_title` | Chaîne | Non | Intitulé court du thème de la session (ex: `"Premiers pas dans le Web"`). |
| `date_debut` | Chaîne | Non | Date de début de session au format `"YYYY-MM-DD"`. |
| `date_fin` | Chaîne | Non | Date de fin de session au format `"YYYY-MM-DD"`. |
| `nav_order` | Entier | **Oui** | Ordre d'affichage dans le menu latéral Just the Docs (1 pour S1, 2 pour S2...). |
| `objectif` | Texte | **Oui** | Ce que l'apprenant doit être capable de réaliser à la fin de la session. |
| `description` | Texte | Non | Synthèse du déroulement et des activités majeures. |
| `uas` | Liste | **Oui** | Liste des codes d'UAs abordées dans la phase 1 (*Apprendre*). |
| `labs` | Liste | Non | Liste des codes de labs de la phase 2 (*Explorer*). |
| `prototype` | Liste | **Oui** | Liste des codes de prototypes de la phase 3 (*Adapter*). |
| `projet_fil_rouge`| Liste | **Oui** | Liste des codes de sprints de la phase 4 (*Transposer*). |

#### Exemple Type Prêt à l'Emploi

```yaml
---
title: "S1 — Premiers pas dans le Web"
tuto_title: "Premiers pas dans le Web"
layout: session
code: "S1"
nav_order: 1
date_debut: "2026-09-07"
date_fin: "2026-09-18"
objectif: >
  Découvrir le fonctionnement d’une application Web, le projet cible, son contexte,
  ses acteurs et les premières données, puis construire de premiers traitements JavaScript.
description: >
  Découvrir le projet cible, un Blog personnel, comprendre sa finalité, son périmètre,
  ses acteurs et ses premières données, construire de premiers traitements JavaScript
  et découvrir les principaux outils de travail à travers des activités pratiques.
uas:
  - "UA.162.11"
  - "UA.111.11"
  - "UA.112.11"
  - "UA.121.11"
  - "UA.161.11"
labs:
  - "L.101"
prototype:
  - "Prototype 1"
projet_fil_rouge:
  - "Sprint 1"
---
```

### 2.2. Collection `uas` (`_uas/[Domaine]/UA.[Code].md`)

Une Unité d'Apprentissage représente un objectif pédagogique précis.

#### Tableau des Champs

| Champ | Type | Obligatoire | Rôle & Description |
| :--- | :--- | :---: | :--- |
| `layout` | Chaîne | **Oui** | Doit être `ua`. |
| `title` | Chaîne | **Oui** | Titre de l'unité d'apprentissage. |
| `code` | Chaîne | **Oui** | Identifiant unique normalisé (ex: `"UA.111.11"`). |
| `ordre` | Entier | **Oui** | Numéro d'ordre au sein du domaine pour le tri séquentiel. |
| `competence` | Chaîne | **Oui** | Code de la compétence parente (ex: `"C.111"`). |
| `domaine` | Chaîne | **Oui** | Code du domaine parent (ex: `"D.111.1"`). |
| `duree` | Nombre | Non | Durée estimée en heures (ex: `1` ou `2`). |
| `objectif` | Texte | **Oui** | Objectif opérationnel visé. |
| `description` | Texte | Non | Description du contenu et du support d'étude. |
| `notions` | Liste | Non | Notions théoriques et techniques clés abordées. |
| `livrable` | Texte | Non | Description du livrable concret attendu de l'apprenant. |
| `travail_a_faire`| Texte | Non | Énoncé succinct du travail pratique à réaliser. |

#### Exemple Type Prêt à l'Emploi

```yaml
---
title: "Identifier le contexte et les acteurs"
layout: ua
code: "UA.111.11"
ordre: 13
competence: "C.111"
domaine: "D.111.1"
duree: 1
objectif: >
  Comprendre la finalité d’une application et repérer les acteurs qui interviennent 
  dans le système.
description: >
  Analyser un support fonctionnel fourni afin d’identifier la finalité générale 
  de l’application, son domaine fonctionnel, son périmètre et les différents 
  acteurs concernés.
notions:
  - "Finalité générale d’une application"
  - "Contexte fonctionnel"
  - "Périmètre fonctionnel"
  - "Identification des acteurs"
  - "Rôles des acteurs"
livrable: >
  Analyse du contexte et des acteurs comprenant Application → Finalité → Acteurs → Rôles.
travail_a_faire: >
  À partir des maquettes d’un Blog personnel, identifier l’application, sa finalité 
  ainsi que les acteurs Administrateur et Visiteur.
---
```

### 2.6. Collection `tutos` (`_tutos/[Domaine]/[ID_Tuto]/[slug].normal.md`)

Les tutoriels guident l'apprenant pas à pas dans l'acquisition d'une notion technique.

#### Tableau des Champs

| Champ | Type | Obligatoire | Rôle & Description |
| :--- | :--- | :---: | :--- |
| `layout` | Chaîne | **Oui** | `tuto` (ou gabarits spécialisés : `analyse`, `conception`, `console`, `git`). |
| `title` | Chaîne | **Oui** | Titre explicite du tutoriel décrivant l'action concrète. |
| `slug` | Chaîne | **Oui** | Nom unique d'URL (kebab-case sans accents). |
| `permalink` | Chaîne | **Oui** | Doit être fixé à `/tutos/:slug/`. |
| `tuto_id` | Chaîne | **Oui** | Identifiant technique du tutoriel (ex: `"T.111.111"`). |
| `ua` | Chaîne | **Oui** | Code de l'UA parente de rattachement (ex: `"UA.111.11"`). |
| `nav_order` | Entier | **Oui** | Ordre d'apparition dans la liste des tutoriels de l'UA. |
| `type` | Chaîne | Non | `"classique"` (lecture + démonstrateur) ou `"interactif"` (avec éditeur). |
| `version` | Chaîne | Non | Version du tutoriel (`"normal"` par défaut). |
| `data_html` | Chaîne | Non | Code HTML initial injecté dans l'éditeur interactif. |
| `data_css` | Chaîne | Non | Code CSS initial injecté dans l'éditeur interactif. |
| `data_js` | Chaîne | Non | Code JS initial injecté dans l'éditeur interactif. |
| `data_php` | Chaîne | Non | Code PHP initial injecté dans l'éditeur interactif. |
| `en_construction` | Booléen | Non | Si `true`, affiche un bandeau prévenant que la page est en révision. |

#### Exemple Type Prêt à l'Emploi

```yaml
---
title: "Comprendre le contexte et les espaces d'un Blog"
layout: tuto
slug: "comprendre-le-contexte-et-les-espaces-d-un-blog"
permalink: /tutos/:slug/
tuto_id: "T.111.111"
ua: "UA.111.11"
nav_order: 1
type: "classique"
version: "normal"
data_html: ""
data_css: ""
data_js: ""
---
```

## 3. Bonnes Pratiques & Pièges YAML à Éviter

1. **Paragraphes multilignes (`>`) :**  
   Pour les descriptions ou objectifs longs, utilisez le chevron `>` suivi d'un saut de ligne. Indentez impérativement le texte de **2 espaces**.
2. **Protection des caractères spéciaux :**  
   Entourez systématiquement vos chaînes de guillemets doubles `"..."` dès qu'elles contiennent un deux-points `:`, un tiret `-` ou un chevron `>`.
3. **Orthographe stricte des clés :**  
   Vérifiez soigneusement l'orthographe des clés (ex: écrivez `objectif:`, ne pas introduire de coquille comme `objePctif:` qui empêcherait l'affichage dans le gabarit).
4. **Validité des identifiants croisés :**  
   Les codes renseignés dans `uas:`, `labs:`, `prototype:` et `projet_fil_rouge:` doivent correspondre **au caractère près** au champ `code:` du fichier cible.
