# Guides Pas-à-Pas de Création d'Entités

## 1. Vue d'Ensemble

Ce manuel opérationnel vous guide pas-à-pas pour créer et publier de nouveaux contenus sur la plateforme **Autoformations Web Solicode**.

Appliquez rigoureusement les étapes ci-dessous pour garantir la cohérence des liens et éviter les erreurs de gabarit Liquid.

---

## 2. Guide 1 : Comment Ajouter une Nouvelle Session

Une session organise le travail pédagogique pour une période donnée (ex: 2 semaines).

### Procédure

1. **Déterminer l'identifiant :**  
   Utilisez la nomenclature `S[N]` (ex: `S1`, `S2`, `S12`).

2. **Créer le fichier :**  
   Dans le dossier `_sessions/`, créez le fichier `S[N].md` (ex: `_sessions/S3.md`).

3. **Compléter le Front Matter :**  
   Copiez le modèle ci-dessous et personnalisez les informations :
   ```yaml
   ---
   title: "S3 — Dynamiser l'Interface Utilisateur"
   tuto_title: "Dynamiser l'Interface Utilisateur"
   layout: session
   code: "S3"
   nav_order: 3
   date_debut: "2026-10-05"
   date_fin: "2026-10-16"
   objectif: >
     Maîtriser les interactions DOM avec JavaScript et structurer les composants interactifs.
   description: >
     Au cours de cette session, vous allez apprendre à écouter les événements utilisateur,
     manipuler les éléments HTML dynamiquement et valider les formulaires de saisie.
   uas:
     - "UA.122.31"
     - "UA.122.32"
   labs:
     - "L.103"
   prototype:
     - "Prototype 3"
   projet_fil_rouge:
     - "Sprint 3"
   ---
   ```

4. **Vérifier les 4 phases de la session :**  
   - Vérifiez que tous les codes déclarés dans `uas:` existent bien dans le dossier `_uas/`.
   - Vérifiez que le prototype déclaré dans `prototype:` existe dans `_prototypes/`.
   - Vérifiez que le sprint déclaré dans `projet_fil_rouge:` existe dans `_projets/`.

5. **Tester l'affichage :**  
   Lancez le serveur local (`.\serve.ps1`) et ouvrez l'URL `http://localhost:4000/autoformations-web/sessions/s3/`.  
   Vérifiez qu'aucun message d'erreur rouge `UA introuvable` ou `Prototype introuvable` n'apparaît.

## 3. Guide 2 : Comment Ajouter une Unité d'Apprentissage (UA)

Une Unité d'Apprentissage représente une notion clé d'une durée type de 1 à 2 heures.

### Procédure

1. **Identifier le rattachement académique :**  
   - Déterminez le domaine parent (ex: `D.122.1` pour HTML).
   - Déterminez la compétence associée (ex: `C.122`).
   - Choisissez un code UA normalisé au format `UA.[CodeDomaine].[Numéro]` (ex: `UA.122.11`).

2. **Créer le fichier :**  
   Dans `_uas/`, repérez le dossier correspondant au domaine (ex: `_uas/D.122.1.html/`).  
   Créez le fichier `UA.[Code].md` (ex: `_uas/D.122.1.html/UA.122.11.md`).

3. **Compléter le Front Matter :**  
   ```yaml
   ---
   title: "Structurer une page avec les balises sémantiques"
   layout: ua
   code: "UA.122.11"
   ordre: 1
   competence: "C.122"
   domaine: "D.122.1"
   duree: 2
   objectif: >
     Comprendre le rôle des balises sémantiques HTML5 et structurer un document accessible.
   description: >
     Découverte des balises structurelles majeures (header, nav, main, section, article, footer)
     et mise en pratique sur une page de blog.
   notions:
     - "Balises de structure HTML5"
     - "Sémantique et accessibilité"
     - "Hiérarchie des titres (h1 à h6)"
   livrable: >
     Page HTML sémantique validée au validateur W3C.
   travail_a_faire: >
     Structurer la maquette fournie en utilisant exclusivement les balises sémantiques adaptées.
   ---
   ```

4. **Rattacher l'UA à la Session :**  
   Ouvrez le fichier de la session concernée (ex: `_sessions/S1.md`) et ajoutez `"UA.122.11"` dans la liste `uas:`.

## 4. Guide 3 : Comment Ajouter un Tutoriel

Les tutoriels guident l'apprenant pas à pas pour acquérir la compétence visée par l'UA.

### Procédure

1. **Créer le dossier et le fichier du tutoriel :**  
   Dans `_tutos/[Domaine]/`, créez un sous-dossier portant l'identifiant du tutoriel (ex: `_tutos/D.122.1-html/T.122.111/`).  
   À l'intérieur, créez le fichier au format `[slug].normal.md` (ex: `balises-semantiques-html.normal.md`).

2. **Compléter le Front Matter :**  
   ```yaml
   ---
   title: "Utiliser les balises sémantiques HTML5"
   layout: tuto
   slug: "balises-semantiques-html"
   permalink: /tutos/:slug/
   tuto_id: "T.122.111"
   ua: "UA.122.11"
   nav_order: 1
   type: "classique"
   version: "normal"
   ---
   ```

3. **(Optionnel) Cas d'un Tutoriel Interactif avec Éditeur de Code :**  
   Si le tutoriel nécessite un éditeur de code multi-onglets (HTML, CSS, JS, PHP) :
   - Définissez `type: "interactif"`.
   - Fournissez le code de départ dans les clés `data_html`, `data_css`, `data_js` :
   ```yaml
   type: "interactif"
   data_html: |
     <main>
       <h1>Titre principal</h1>
       <p>Contenu à modifier...</p>
     </main>
   data_css: |
     main { max-width: 800px; margin: auto; }
   data_js: ""
   ```

4. **Rédiger le corps pédagogique du tutoriel :**  
   Appliquez la progression didactique sans rupture :
   - `## 1. Objectif` : Présentation claire de ce que l'apprenant va réaliser.
   - `## 2. Prérequis` : Liens vers la maquette ou les acquis nécessaires.
   - `## 3. Théorie (Comprendre)` : Notions expliquées en français simple (A1–A2) avec glossaire concis.
   - `## 4. Exemple Concret (Observer)` : Démonstrateur ou extrait de code du Blog.
   - `## 5. Exercice Pratique (Réaliser)` : Consigne d'action concrète avec résultat attendu.

5. **Vérifier l'affichage :**  
   Ouvrez la page de l'UA correspondante : le nouveau tutoriel doit y figurer automatiquement dans la section **Tutoriels**.

## 5. Guide 4 : Comment Ajouter un Lab, un Prototype ou un Sprint

Les activités d'exploration, d'adaptation et de transposition complètent la session.

### 5.1. Ajouter un Lab (`_labs/`)

Créez le fichier `_labs/L.[Code].md` (ex: `_labs/L.102.md`) :
```yaml
---
title: "Lab — Tester les sélecteurs CSS complexes"
layout: default
code: "L.102"
session: "S2"
type: "lab"
objectif: >
  Expérimenter les sélecteurs CSS avancés et pseudo-classes sur des cas réels.
livrable: >
  Fiche récapitulative commentée avec exemples de tests.
---
```

### 5.2. Ajouter un Prototype (`_prototypes/`)

Créez le fichier `_prototypes/Prototype [X].md` (ex: `_prototypes/Prototype 2.md`) :
```yaml
---
title: "Intégrer la structure de votre Portfolio"
layout: prototype
code: "Prototype 2"
session: "S2"
travail_a_faire: >
  Créer la structure HTML sémantique de la page d'accueil de votre Portfolio personnel.
livrable:
  - "Dépôt GitHub du Portfolio"
  - "Lien de la page publiée sur GitHub Pages"
---
```

### 5.3. Ajouter un Sprint Projet Fil Rouge (`_projets/`)

Créez le fichier `_projets/Sprint [X].md` (ex: `_projets/Sprint 2.md`) :
```yaml
---
title: "Sprint 2 — Intégration de la maquette publique du Blog"
layout: projet-fil-rouge
code: "Sprint 2"
session: "S2"
travail_a_faire: >
  Intégrer les pages d'accueil et de détail d'un article du Blog en équipe
  en respectant les maquettes validées.
livrable:
  - "Pull Request validée sur le dépôt d'équipe"
  - "Page de prévisualisation conforme aux maquettes"
---
```

## 6. Checklist de Contrôle Qualité avant Publication

Avant de valider ou de pousser vos modifications sur le dépôt Git, effectuez ces 5 vérifications :

- [ ] **1. Encodage :** Tous les nouveaux fichiers sont-ils en **UTF-8 sans BOM** ?
- [ ] **2. Zéro style inline :** Aucun attribut `style="..."` ni balise `<style>` n'a été inséré dans le Markdown ?
- [ ] **3. Intégrité des clés de liaison :**
  - Les codes `uas` de la session correspondent exactement aux `code:` des fichiers `_uas/`.
  - Le code `ua:` de chaque tutoriel pointe vers une UA existante.
  - Le code `prototype` et `projet_fil_rouge` pointent vers des fichiers existants.
- [ ] **4. Clarté éditoriale :** Les phrases sont courtes, le ton est direct à l'impératif, et le nom de l'établissement est **Solicode** (interdiction de *Spartel Dev Academy*).
- [ ] **5. Test local de build :** Le site compile-t-il sans erreur ?
  ```powershell
  bundle exec jekyll build
  ```
